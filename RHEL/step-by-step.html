RKE2 Airgap Upgrade Guide — RHEL / Rocky / AlmaLinux

RHEL 8 / 9 Rocky Linux 8/9 AlmaLinux 8/9 ⚠ One minor version at a time v1.27 → v1.32 path

1RHEL vs Ubuntu — Key Differences

This guide covers the same upgrade path as the Ubuntu runbook (v1.27 → v1.32) but addresses the system-level differences that apply to RHEL-family distributions. If you are migrating from the Ubuntu guide, focus on the sections marked RHEL.

AreaUbuntuRHEL / Rocky / Alma
Security moduleAppArmor (optional)SELinux — mandatory, must configure
Firewallufw / iptablesfirewalld — explicit port rules required
Network managementnetplan / systemd-networkdNetworkManager — must disable cloud-setup service
Package managerapt / dpkgdnf / rpm (not used for airgap tarball install)
Kernel modulesmodprobe.d / /etc/modulesmodules-load.d — different persistence path
RKE2 SELinux policyNot requiredrke2-selinux RPM must be installed before RKE2
nm-cloud-setupNot presentMust be disabled — breaks pod networking

🎩
SELinux and NetworkManager are the two most common failure causes on RHEL New operators who skip the SELinux policy install or forget to disable nm-cloud-setup.service will see pods stuck in ContainerCreating or nodes unable to join. These are not optional steps.

2Upgrade Path

The upgrade path is identical to the Ubuntu guide. RHEL has no special version restrictions beyond the standard Kubernetes one-minor-version rule.

v1.27.x+rke2r1 → v1.28.9+rke2r1 → v1.29.9+rke2r1 → v1.30.9+rke2r1 → v1.31.9+rke2r1 → v1.32.13+rke2r1
⚠
Never skip a minor version Even on RHEL, you must step through each intermediate release. Attempting to jump from 1.27 to 1.32 will fail or corrupt etcd.

3Prerequisites

RHEL-specific packages

Install the following packages before the first RKE2 install. In an airgap environment, download these RPMs and their dependencies on a connected machine and transfer them.

# Install required packages
dnf install -y \
  container-selinux \
  iptables \
  libnetfilter_conntrack \
  libnfnetlink \
  libnftnl \
  nfs-utils \
  cryptsetup

# RHEL 8 only: switch to legacy iptables backend
# (nftables default causes issues with Kubernetes network policies)
update-alternatives --set iptables /usr/sbin/iptables-legacy
update-alternatives --set ip6tables /usr/sbin/ip6tables-legacy
🎩
RHEL 9: iptables-legacy is no longer available On RHEL 9, nftables is the only backend. RKE2 ≥ 1.29 uses Canal/Flannel which works with nftables, so no backend switch is needed. On RHEL 8, the iptables-legacy switch is still recommended for Kubernetes 1.27–1.28.

Disable swap

swapoff -a
# Persist across reboots
sed -i '/\sswap\s/d' /etc/fstab

System limits

# Increase open file limits
cat >> /etc/security/limits.conf <<'EOF'
* soft nofile 1048576
* hard nofile 1048576
* soft nproc  unlimited
* hard nproc  unlimited
EOF

4SELinux Configuration RHEL

🎩 This section has no Ubuntu equivalent — required on all RHEL-family systems.

RKE2 ships a dedicated SELinux policy package (rke2-selinux) that must be installed before RKE2 itself. Without it, containerd, kubelet, and pod processes will be denied by SELinux and workloads will fail to start.

🛑
Do not set SELinux to Permissive in production Setting SELINUX=permissive in /etc/selinux/config disables all MAC enforcement and is a serious security regression. Use the rke2-selinux policy package instead — it permits exactly the operations RKE2 needs while keeping SELinux enforcing.

Install rke2-selinux (airgap)

Download the RPM on an internet-connected machine and transfer it to the airgap node.

# On the internet-connected machine — download the policy RPM
# For RHEL 8:
curl -LO "https://github.com/rancher/rke2-selinux/releases/download/v0.19.stable.1/rke2-selinux-0.19-1.el8.noarch.rpm"
# For RHEL 9:
curl -LO "https://github.com/rancher/rke2-selinux/releases/download/v0.19.stable.1/rke2-selinux-0.19-1.el9.noarch.rpm"
# On the airgap node — install the policy
# RHEL 8:
rpm -ivh /root/rke2-setup/rke2-selinux-0.19-1.el8.noarch.rpm
# RHEL 9:
rpm -ivh /root/rke2-setup/rke2-selinux-0.19-1.el9.noarch.rpm

# Verify the policy was loaded
semodule -l | grep rke2

Verify SELinux is enforcing

getenforce
# Must output: Enforcing

# If Permissive or Disabled, enable it:
setenforce 1
# And persist:
sed -i 's/^SELINUX=.*/SELINUX=enforcing/' /etc/selinux/config

After each RKE2 upgrade — relabel if needed

When RKE2 adds new files, they may need SELinux context relabeling. If you see AVC denials after an upgrade:

# Check for recent AVC denials related to RKE2
ausearch -m AVC -ts recent 2>/dev/null | grep rke2 | head -20

# Relabel RKE2 directories
restorecon -Rv /var/lib/rancher/rke2/
restorecon -Rv /usr/local/lib/systemd/system/rke2-*.service

5Firewalld Configuration RHEL

🎩 Ubuntu uses ufw or no firewall. RHEL enables firewalld by default — all required ports must be opened explicitly.

RKE2 requires several ports for intra-cluster communication. Open them permanently with firewall-cmd.

Server node firewall rules

# RKE2 server node — open required ports
firewall-cmd --permanent --add-port=6443/tcp   # Kubernetes API server
firewall-cmd --permanent --add-port=9345/tcp   # RKE2 supervisor API
firewall-cmd --permanent --add-port=2379/tcp   # etcd client
firewall-cmd --permanent --add-port=2380/tcp   # etcd peer
firewall-cmd --permanent --add-port=10250/tcp  # kubelet API
firewall-cmd --permanent --add-port=10257/tcp  # kube-controller-manager
firewall-cmd --permanent --add-port=10259/tcp  # kube-scheduler
firewall-cmd --permanent --add-port=4789/udp   # Calico VXLAN overlay (IANA standard)
firewall-cmd --permanent --add-port=5473/tcp   # Calico Typha (larger clusters)

# NodePort range
firewall-cmd --permanent --add-port=30000-32767/tcp
firewall-cmd --permanent --add-port=30000-32767/udp

# Apply all changes
firewall-cmd --reload

# Verify
firewall-cmd --list-ports

Agent node firewall rules

# RKE2 agent node — a subset of server rules
firewall-cmd --permanent --add-port=10250/tcp  # kubelet API
firewall-cmd --permanent --add-port=4789/udp   # Calico VXLAN overlay
firewall-cmd --permanent --add-port=30000-32767/tcp
firewall-cmd --permanent --add-port=30000-32767/udp
firewall-cmd --reload
ℹ
Single-node clusters can disable firewalld safely On a single-node dev or lab cluster where all traffic is local, you can disable firewalld: systemctl disable --now firewalld. For production multi-node clusters, always use the explicit port list above.

6NetworkManager Configuration RHEL

🎩 This is the most common source of pod networking failures on RHEL. Do not skip this section.

Disable nm-cloud-setup

nm-cloud-setup.service continuously reconfigures network interfaces for cloud environments. It will overwrite the routing tables that Canal/Flannel sets up for pod networking, causing ContainerCreating pods that never start.

# Disable the cloud network setup timer and service
systemctl disable --now nm-cloud-setup.service nm-cloud-setup.timer 2>/dev/null || true

# Verify they are inactive
systemctl is-active nm-cloud-setup.service nm-cloud-setup.timer 2>/dev/null
# Expected: inactive (or Unit not found — also fine)

Tell NetworkManager to ignore the CNI interfaces

Without this, NetworkManager will manage the virtual cni0, vxlan.calico, and cali* interfaces that Calico creates, and may reset them when it detects changes.

cat > /etc/NetworkManager/conf.d/rke2-cni.conf <<'EOF'
[keyfile]
unmanaged-devices=interface-name:cni0;interface-name:vxlan.calico;interface-name:veth*;interface-name:cali*
EOF

systemctl reload NetworkManager

Verify the network interface config

# Confirm the node's primary interface is managed
nmcli device status

# Confirm RKE2's CNI interfaces are unmanaged
nmcli device status | grep -E "cni0|vxlan|cali|veth"
# Expected output: unmanaged

7Kernel Parameters & Modules

These parameters are required by Kubernetes on all Linux distributions. RHEL uses /etc/modules-load.d/ for module persistence (different path from some Ubuntu setups).

# Load required kernel modules now
modprobe overlay
modprobe br_netfilter

# Persist across reboots (RHEL path)
cat > /etc/modules-load.d/rke2.conf <<'EOF'
overlay
br_netfilter
EOF

# Set required sysctl parameters
cat > /etc/sysctl.d/99-rke2.conf <<'EOF'
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF

# Apply immediately
sysctl --system

# Verify
sysctl net.bridge.bridge-nf-call-iptables net.ipv4.ip_forward
🎩
RHEL 9 ships with br_netfilter as a built-in On RHEL 9, br_netfilter may already be compiled into the kernel. modprobe will succeed silently even if that is the case, so the commands above are safe to run on both RHEL 8 and 9.

8Download Artifacts

Artifacts are identical to the Ubuntu guide — the RKE2 tarball is the same binary regardless of OS. Download on an internet-connected machine, verify checksums, then transfer.

The RHEL/scripts/download-artifacts.sh script handles this automatically. See the Script Reference section for usage.

# Manual download for a single version (example: v1.28.9+rke2r1)
VERSION="v1.28.9+rke2r1"
ENCODED="v1.28.9%2Brke2r1"
OUTDIR="./rke2-airgap/${VERSION}"
mkdir -p "$OUTDIR"

curl -fL "https://github.com/rancher/rke2/releases/download/${ENCODED}/rke2.linux-amd64.tar.gz" \
  -o "$OUTDIR/rke2.linux-amd64.tar.gz"
curl -fsSL "https://github.com/rancher/rke2/releases/download/${ENCODED}/sha256sum-amd64.txt" \
  -o "$OUTDIR/sha256sum-amd64.txt"

# Verify
cd "$OUTDIR" && sha256sum -c sha256sum-amd64.txt --ignore-missing
🎩
Also download the rke2-selinux RPM In addition to the version tarballs, download the rke2-selinux RPM for your RHEL major version and add it to the transfer package. See Section 4. If the cluster has never had RKE2 installed, this RPM must be installed before the first RKE2 binary.

9Transfer to Airgap Environment

# Transfer all artifacts from the download machine
scp -r ./rke2-airgap/ admin@<airgap-server-ip>:/root/rke2-upgrade/

# Re-verify checksums on the airgap node after transfer
for dir in /root/rke2-upgrade/v*/; do
  echo "Verifying $(basename $dir) ..."
  cd "$dir"
  sha256sum -c sha256sum-amd64.txt --ignore-missing 2>&1 | grep -E "OK|FAILED"
  cd - >/dev/null
done

10etcd Snapshot (Backup)

Take a manual snapshot before each upgrade step. The command is identical on RHEL and Ubuntu.

rke2 etcd-snapshot save --name "pre-upgrade-$(date +%Y%m%d%H%M)"

# Verify
ls -lh /var/lib/rancher/rke2/server/db/snapshots/ | tail -3

11Server Node Upgrade

Repeat for each version in the upgrade path. The install procedure is identical to Ubuntu because we use the tarball installer, not RPM packages.

ℹ
Tarball install vs RPM install RKE2 can be installed via RPM (dnf install rke2-server) or via the tarball installer. For airgap environments, the tarball method is simpler because RPM installation requires either a local DNF repository or manual dependency resolution. The upgrade scripts in this guide use the tarball installer exclusively.
  1. Verify SELinux policy is current 
    semodule -l | grep rke2
# Should show: rke2  (version number)
  2. Take an etcd snapshot 
    rke2 etcd-snapshot save --name "pre-$(date +%Y%m%d%H%M)"
  3. Install the new binary from the airgap tarball 
    TARGET_VERSION="v1.28.9+rke2r1"
INSTALL_RKE2_ARTIFACT_PATH="/root/rke2-upgrade/${TARGET_VERSION}" \
  INSTALL_RKE2_VERSION="${TARGET_VERSION}" \
  bash /root/rke2-upgrade/install.sh
  4. Verify binary version 
    rke2 --version | head -1
  5. Restart the server service 
    systemctl restart rke2-server

    On RHEL, SELinux may log AVC denials during the first restart after an upgrade while new file contexts are applied. These are transient and the service will come up. Check with journalctl -u rke2-server -f.

  6. Wait for active, then verify node Ready 
    until systemctl is-active rke2-server >/dev/null 2>&1 || \
    systemctl is-failed rke2-server >/dev/null 2>&1; do sleep 5; done
systemctl is-active rke2-server && echo UP || echo FAILED
kubectl get nodes
  7. Wait for system pods 
    kubectl rollout status -n kube-system daemonset/calico-node --timeout=120s
kubectl rollout status -n kube-system deployment/rke2-coredns-rke2-coredns --timeout=120s
  8. Repeat from step 1 with the next version

12Agent Node Upgrade

Apply the same RHEL system preparation (SELinux, firewalld, NetworkManager) to every agent node before upgrading it. Then follow the same cordon/drain/upgrade/uncordon sequence as Ubuntu.

# From the server: cordon and drain
kubectl cordon <agent-node-name>
kubectl drain <agent-node-name> --ignore-daemonsets --delete-emptydir-data

# On the agent node:
TARGET_VERSION="v1.32.13+rke2r1"
INSTALL_RKE2_ARTIFACT_PATH="/root/rke2-upgrade/${TARGET_VERSION}" \
  INSTALL_RKE2_VERSION="${TARGET_VERSION}" \
  INSTALL_RKE2_TYPE="agent" \
  bash /root/rke2-upgrade/install.sh
systemctl restart rke2-agent

# Back on the server: verify and uncordon
kubectl get node <agent-node-name>
kubectl uncordon <agent-node-name>

13Verification

# Cluster version and node state
kubectl get nodes -o wide
kubectl version

# All pods — flag non-Running
kubectl get pods -A | grep -v "Running\|Completed" | grep -v "NAME"

# No AVC denials from RKE2 since upgrade
ausearch -m AVC -ts recent 2>/dev/null | grep -c rke2 || echo "0 AVC denials"

# No node taints
kubectl describe node | grep -E "Taint"

# CoreDNS resolution
kubectl run -it --rm dns-test --image=busybox --restart=Never -- \
  nslookup kubernetes.default.svc.cluster.local

14Custom Images

The containerd major version bump (1.7→2.x on the 1.27→1.32 path) evicts locally-imported images on RHEL exactly as it does on Ubuntu. Re-import using ctr.

# Check what custom images are loaded
/var/lib/rancher/rke2/bin/ctr \
  --address /run/k3s/containerd/containerd.sock \
  -n k8s.io images ls | grep -v "rancher\|k8s.gcr\|registry.k8s"

# Re-import a missing image
/var/lib/rancher/rke2/bin/ctr \
  --address /run/k3s/containerd/containerd.sock \
  -n k8s.io images import /path/to/image.tar

# Restart affected deployments
kubectl rollout restart deployment/<name> -n <namespace>
🎩
If Docker is installed on RHEL: use Podman instead RHEL ships with Podman by default and Docker may not be installed. To export an image with Podman: podman save my-image:tag | ctr --address /run/k3s/containerd/containerd.sock -n k8s.io images import -

15Disk Cleanup

# Remove old RKE2 data directories (each step leaves ~300 MB)
CURRENT=$(rke2 --version | awk '{print $3}' | sed 's/+/-/')
for dir in /var/lib/rancher/rke2/data/*/; do
  if ! echo "$(basename $dir)" | grep -q "$CURRENT"; then
    echo "Removing: $(basename $dir)"
    rm -rf "$dir"
  fi
done
df -h /

16Rollback

Rollback procedure is identical to Ubuntu: stop the service, re-install the previous binary, restore etcd from snapshot. No RHEL-specific steps are needed beyond ensuring the SELinux policy version matches the binary version being restored.

systemctl stop rke2-server

PREV_VERSION="v1.31.9+rke2r1"
INSTALL_RKE2_ARTIFACT_PATH="/root/rke2-upgrade/${PREV_VERSION}" \
  INSTALL_RKE2_VERSION="${PREV_VERSION}" \
  bash /root/rke2-upgrade/install.sh

SNAPSHOT_NAME="pre-upgrade-202611220000"
rke2 server \
  --cluster-reset \
  --cluster-reset-restore-path=/var/lib/rancher/rke2/server/db/snapshots/${SNAPSHOT_NAME}

systemctl start rke2-server

17Troubleshooting (RHEL-specific)

Pods stuck in ContainerCreating — SELinux AVC denial

# Check for AVC denials
ausearch -m AVC -ts recent 2>/dev/null | grep -E "rke2|containerd|kubelet"

# Install or update the SELinux policy
rpm -ivh --replacepkgs /root/rke2-setup/rke2-selinux-*.rpm
semodule -l | grep rke2

# Relabel RKE2 paths
restorecon -Rv /var/lib/rancher/rke2/

Pods not scheduling — nm-cloud-setup resetting routes

# Confirm the service is disabled
systemctl is-active nm-cloud-setup.service nm-cloud-setup.timer

# If still active, disable and reboot
systemctl disable --now nm-cloud-setup.service nm-cloud-setup.timer
# Restart networking
systemctl restart NetworkManager
# Then restart RKE2 to re-establish CNI routes
systemctl restart rke2-server

Agent cannot reach server — firewalld blocking port 9345

# Test from the agent node
curl -k https://<server-ip>:9345/ping

# If it hangs, open the port on the SERVER
firewall-cmd --permanent --add-port=9345/tcp
firewall-cmd --reload

rke2-server fails to start — journal shows SELinux denials

# See if SELinux is blocking the binary itself
ausearch -m AVC -ts recent 2>/dev/null | grep rke2 | tail -5

# Temporarily set to permissive to confirm SELinux is the cause
setenforce 0
systemctl restart rke2-server
# If it starts: re-enable and fix the policy
setenforce 1
# Update the rke2-selinux RPM to its latest version

Disk pressure / eviction threshold

# Check disk — same thresholds as Ubuntu (nodefs.available < 5% = eviction)
df -h /var/lib/rancher/rke2/

# Remove old data dirs
ls /var/lib/rancher/rke2/data/
# Keep only current, remove old v1.{28,29,30,31}.* directories

# Check for taint
kubectl describe node | grep Taint

18Script Reference

All scripts are in the RHEL/scripts/ directory. They wrap the procedures in this guide with RHEL-aware checks (SELinux, firewalld, NetworkManager).

ScriptWhat it doesRun on
prepare-node.sh One-time RHEL system setup: kernel modules, sysctl, swap, NetworkManager CNI config, SELinux policy install Server & agent nodes (once)
open-firewall.sh Opens all required firewalld ports for a server or agent node Server & agent nodes (once)
download-artifacts.sh Downloads all version tarballs + rke2-selinux RPM on an internet machine Internet-connected machine
upgrade-server.sh Installs one version step, restarts rke2-server, verifies Ready Server node (each step)
upgrade-agent.sh Upgrades an agent node with cordon/drain gate Agent node
post-upgrade-cleanup.sh Removes old RKE2 data directories, reports disk reclaimed Server node (once after final step)

Typical run order

# 1. First time only — prepare node and open firewall
sudo bash RHEL/scripts/prepare-node.sh
sudo bash RHEL/scripts/open-firewall.sh server

# 2. Download artifacts (internet-connected machine)
bash RHEL/scripts/download-artifacts.sh ./rke2-airgap

# 3. Transfer to server and upgrade step by step
bash RHEL/scripts/upgrade-server.sh v1.28.9+rke2r1 /root/rke2-upgrade
bash RHEL/scripts/upgrade-server.sh v1.29.9+rke2r1 /root/rke2-upgrade
bash RHEL/scripts/upgrade-server.sh v1.30.9+rke2r1 /root/rke2-upgrade
bash RHEL/scripts/upgrade-server.sh v1.31.9+rke2r1 /root/rke2-upgrade
bash RHEL/scripts/upgrade-server.sh v1.32.13+rke2r1 /root/rke2-upgrade

# 4. Clean up
bash RHEL/scripts/post-upgrade-cleanup.sh

19Full Checklist

One-time RHEL node preparation (all nodes)

  • Swap disabled (swapoff -a + removed from /etc/fstab)
  • container-selinux, iptables, nfs-utils packages installed
  • RHEL 8: iptables-legacy backend set via update-alternatives
  • Kernel modules overlay and br_netfilter loaded and persisted in /etc/modules-load.d/rke2.conf
  • sysctl parameters set in /etc/sysctl.d/99-rke2.conf and applied
  • nm-cloud-setup.service and nm-cloud-setup.timer disabled
  • NetworkManager CNI ignore config written to /etc/NetworkManager/conf.d/rke2-cni.conf
  • rke2-selinux RPM installed; semodule -l | grep rke2 confirms policy loaded
  • SELinux is Enforcing (getenforce)
  • Firewalld rules applied for all required ports

Before each upgrade

  • Disk free on / ≥ 20 GB
  • All nodes Ready
  • etcd snapshot taken
  • Artifact tarball present and checksum verified

After each upgrade step

  • No AVC denials for RKE2 processes (ausearch -m AVC -ts recent | grep rke2)
  • Node shows Ready at new version
  • Canal, CoreDNS rollout complete

After final upgrade step

  • All agent nodes upgraded and uncordoned
  • All application pods Running
  • Custom images confirmed in containerd store
  • Old RKE2 data directories removed
  • No node taints
  • Post-upgrade etcd snapshot saved
