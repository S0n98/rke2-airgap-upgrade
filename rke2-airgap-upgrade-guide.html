RKE2 Airgap Cluster Upgrade Guide

✓ Verified on v1.27 → v1.32 ⚠ One-minor-version increments only Ubuntu 24.04 · RKE2

1Introduction

This guide covers in-place upgrades of an RKE2 cluster in an airgap (internet-isolated) environment. All binary tarballs, container images, and checksums must be downloaded on an internet-connected machine and transferred to the airgap environment before beginning the upgrade.

⚠
One minor version at a time Kubernetes and RKE2 do not support skipping minor versions during an upgrade. You must upgrade sequentially: 1.27 → 1.28 → 1.29 → … → target. Attempting to jump multiple minor versions will fail or corrupt etcd state.
🛑
Disk space: minimum 20 GB free before starting Each upgrade step extracts ~300 MB into /var/lib/rancher/rke2/data/. With 5 intermediate steps this totals ~1.5 GB. If disk usage exceeds the kubelet's eviction threshold (nodefs.available < 5%), the node will be tainted NoSchedule and pods will not reschedule. Clean up unused images and old RKE2 data directories before upgrading.

2Upgrade Path

This cluster was upgraded from v1.27.13 to v1.32.13 in five sequential steps. Use the same path for any cluster on 1.27.

v1.27.13+rke2r1 → v1.28.9+rke2r1 → v1.29.9+rke2r1 → v1.30.9+rke2r1 → v1.31.9+rke2r1 → v1.32.13+rke2r1

3Cluster Architecture

An RKE2 cluster has two node roles. This guide covers upgrading both.

RoleSystemd ServiceConfig PathWhat it runs
Server node
control-plane + etcd		 rke2-server /etc/rancher/rke2/config.yaml API server, controller manager, scheduler, etcd, kubelet, Canal CNI
Agent node
worker only		 rke2-agent /etc/rancher/rke2/config.yaml kubelet, kube-proxy, containerd, Canal CNI
ℹ
Upgrade order: server first, agents after Always upgrade the server node(s) before agent nodes. The Kubernetes API server must be at the target version before worker kubelets are upgraded. In a multi-server HA setup, upgrade one server at a time and verify it rejoins the cluster before upgrading the next.

4Prerequisites

Confirm all items below on the internet-connected download machine and the target airgap node before downloading artifacts.

On the airgap node — verify before starting

  • Free disk space on / is at least 20 GB (df -h /)
  • Current cluster is healthy: kubectl get nodes shows all nodes Ready
  • No node taints blocking scheduling: kubectl describe node <name> | grep Taint
  • etcd snapshot taken within the last hour (see section 7)
  • All custom container images saved as tar archives and confirmed present
  • No active Kubernetes upgrade jobs or pending evictions

On the download machine

  • Internet access to github.com and GitHub release CDN
  • Sufficient disk space for all upgrade tarballs (~350 MB × number of steps)
  • curl, sha256sum, and scp or equivalent transfer tool available
  • Target RKE2 version confirmed available on GitHub Releases

5Download Artifacts (internet-connected machine)

For each version in the upgrade path, download the RKE2 tarball, its checksum file, and the install script. Store each in its own directory.

ℹ
Container images are already embedded The RKE2 tarball includes all required system component images (etcd, CoreDNS, Canal, metrics-server, ingress-nginx, snapshot-controller) as tar files in ./share/rke2/agent/images/. No separate image pull is needed for system components. Only your custom application images need to be handled separately (see section 12).
Download script — run on the internet-connected machine
#!/bin/bash
# Run on the internet-connected download machine

RKE2_VERSIONS=(
  "v1.28.9+rke2r1"
  "v1.29.9+rke2r1"
  "v1.30.9+rke2r1"
  "v1.31.9+rke2r1"
  "v1.32.13+rke2r1"
)

DOWNLOAD_DIR="./rke2-airgap-upgrade"
mkdir -p "$DOWNLOAD_DIR"

# Download the install script once
curl -sL https://get.rke2.io -o "$DOWNLOAD_DIR/install.sh"
chmod +x "$DOWNLOAD_DIR/install.sh"

for VERSION in "${RKE2_VERSIONS[@]}"; do
  ENCODED=$(echo "$VERSION" | sed 's/+/%2B/')
  DIR="$DOWNLOAD_DIR/$VERSION"
  mkdir -p "$DIR"
  echo "=== Downloading $VERSION ==="

  # Tarball
  curl -L --progress-bar \
    "https://github.com/rancher/rke2/releases/download/${ENCODED}/rke2.linux-amd64.tar.gz" \
    -o "$DIR/rke2.linux-amd64.tar.gz"

  # Checksum
  curl -sL \
    "https://github.com/rancher/rke2/releases/download/${ENCODED}/sha256sum-amd64.txt" \
    -o "$DIR/sha256sum-amd64.txt"

  # Verify download integrity
  cd "$DIR"
  sha256sum -c sha256sum-amd64.txt --ignore-missing 2>&1 | grep -E "OK|FAILED"
  cd - >/dev/null
done

echo ""
echo "Downloaded $(du -sh $DOWNLOAD_DIR | cut -f1) total"
echo "Files ready in: $DOWNLOAD_DIR/"
⚠
Always verify checksums before transferring A corrupted tarball will silently install a broken binary. The sha256sum -c check above must show rke2.linux-amd64.tar.gz: OK for every version before you proceed.

6Transfer Artifacts to Airgap Environment

Use your organization's standard file transfer method (SCP, USB, shared NFS mount, S3-compatible store with one-way sync, etc.).

# From the download machine — transfer the entire directory
scp -r ./rke2-airgap-upgrade/ admin@<airgap-server-ip>:/root/rke2-upgrade/

# Or, if using rsync:
rsync -avz --progress ./rke2-airgap-upgrade/ admin@<airgap-server-ip>:/root/rke2-upgrade/

On the airgap node, re-verify checksums after transfer to detect any corruption during transit:

# On the airgap server node — verify after transfer
for dir in /root/rke2-upgrade/v*/; do
  echo "Verifying $(basename $dir) ..."
  cd "$dir"
  sha256sum -c sha256sum-amd64.txt --ignore-missing 2>&1 | grep -E "OK|FAILED"
  cd - >/dev/null
done

7Backup & etcd Snapshot

Always take a fresh etcd snapshot immediately before upgrading. RKE2 stores automated snapshots in /var/lib/rancher/rke2/server/db/snapshots/; the command below takes a manual on-demand one.

# Take a named snapshot before upgrading
rke2 etcd-snapshot save --name pre-upgrade-$(date +%Y%m%d%H%M)

# Verify the snapshot was created
ls -lh /var/lib/rancher/rke2/server/db/snapshots/ | tail -5

# Optional: copy to a safe location outside the cluster node
scp /var/lib/rancher/rke2/server/db/snapshots/pre-upgrade-* \
    backup-host:/backups/rke2-etcd/
✓
RKE2 also takes automated snapshots every 12 hours The five most recent snapshots are kept by default. The retention count is configurable via etcd-snapshot-retention in /etc/rancher/rke2/config.yaml.

Snapshot disk usage

Each snapshot is roughly 10–50 MB depending on etcd data size. With the default retention of 5, this is negligible. If your etcd data is large (many CRDs, secrets, or long-lived clusters), consider temporarily setting retention to 2–3 before the upgrade to free space.

8Server Node Upgrade Procedure

Repeat this procedure for each version in the upgrade path. Do not skip versions.

⚠
Brief downtime expected On a single-node cluster there is no way to avoid a control-plane outage during the restart. The API server will be unavailable for 30–90 seconds per step. Running workloads are unaffected if they don't depend on the API server.

Step-by-step for each version

  1. Set the version variable 
    TARGET_VERSION="v1.28.9+rke2r1"   # Change per step
  2. Install the new binary from the airgap tarball
    Offline install using local tarball
    INSTALL_RKE2_ARTIFACT_PATH="/root/rke2-upgrade/${TARGET_VERSION}" \
  INSTALL_RKE2_VERSION="${TARGET_VERSION}" \
  bash /root/rke2-upgrade/install.sh

    The INSTALL_RKE2_ARTIFACT_PATH variable tells the installer to use the local tarball instead of downloading from GitHub. The install script extracts the binary to /usr/local/bin/rke2 and updates the systemd unit file.

  3. Verify the binary version before restarting 
    rke2 --version | head -1
# Expected: rke2 version v1.28.9+rke2r1 (...)
  4. Restart the RKE2 server service 
    systemctl restart rke2-server

    The service will stop the old process, start the new binary, migrate etcd schema if needed, and restart system component pods. The first attempt may show a brief CRD registration error in journal logs — this is normal; systemd will retry and the service will succeed.

  5. Wait for the service to become active 
    until systemctl is-active rke2-server >/dev/null 2>&1 || \
      systemctl is-failed rke2-server >/dev/null 2>&1; do
  sleep 5
done
systemctl is-active rke2-server && echo "UP" || echo "FAILED"
  6. Verify the node is Ready at the new version 
    kubectl get nodes
# NAME   STATUS   ROLES                       AGE    VERSION
# rag    Ready    control-plane,etcd,master   171d   v1.28.9+rke2r1
  7. Wait for system pods to be Ready 
    kubectl rollout status -n kube-system daemonset/rke2-canal --timeout=120s
kubectl rollout status -n kube-system deployment/rke2-coredns-rke2-coredns --timeout=120s
kubectl rollout status -n kube-system deployment/rke2-metrics-server --timeout=120s
  8. Repeat from step 1 with the next version in the path

    Only proceed to the next minor version after the node shows Ready and all system pods are Running.

ℹ
If the service fails to start Check journal logs: journalctl -u rke2-server --since "2 minutes ago" --no-pager | grep -E "fatal|Error". Common causes: insufficient disk space, containerd socket not ready, or a CRD registration race condition (usually resolves on the next systemd retry within 10–30 s).

9Agent Node Upgrade Procedure

Upgrade agent (worker) nodes after the server node has been fully upgraded to the target version. For each agent node, follow these steps.

⚠
Cordon and drain each agent before upgrading it This moves workloads to other nodes and prevents new pods from being scheduled during the upgrade window. Skip this if you have only one agent node or if downtime is acceptable. 
# From the server node — cordon and drain the agent
AGENT_NODE="worker-01"   # Replace with your agent node name

kubectl cordon "${AGENT_NODE}"
kubectl drain "${AGENT_NODE}" \
  --ignore-daemonsets \
  --delete-emptydir-data \
  --timeout=120s

Then, on the agent node itself:

# On the agent node — set variables
TARGET_VERSION="v1.32.13+rke2r1"   # Must match server version

# Install the new binary from the airgap tarball
INSTALL_RKE2_ARTIFACT_PATH="/root/rke2-upgrade/${TARGET_VERSION}" \
  INSTALL_RKE2_VERSION="${TARGET_VERSION}" \
  INSTALL_RKE2_TYPE="agent" \
  bash /root/rke2-upgrade/install.sh

# Verify binary
rke2 --version | head -1

# Restart the agent service
systemctl restart rke2-agent

# Wait for it to become active
until systemctl is-active rke2-agent >/dev/null 2>&1 || \
    systemctl is-failed rke2-agent >/dev/null 2>&1; do sleep 5; done
systemctl is-active rke2-agent && echo "UP" || echo "FAILED"

Back on the server node, verify the agent rejoined and uncordon it:

# From the server — verify agent is Ready at new version
kubectl get node "${AGENT_NODE}"
# Expected: STATUS=Ready, VERSION=v1.32.13+rke2r1

# Uncordon to allow scheduling
kubectl uncordon "${AGENT_NODE}"
ℹ
Agent upgrades do not need to be sequential by minor version Unlike the server node, agent nodes can jump directly to the final target version — as long as the server is already there. The kubelet version must be ≤ the API server version, so once the server is on 1.32 you may upgrade any agent directly to 1.32.

10Verification

After completing all upgrade steps, run the following checks to confirm the cluster and all services are healthy.

# 1. Cluster version and node state
kubectl get nodes -o wide
kubectl version

# 2. All system pods running
kubectl get pods -n kube-system

# 3. All application pods by namespace
kubectl get pods -A | grep -v "ContainerStatusUnknown\|Completed" \
  | awk '$4!="Running" {print "PROBLEM: "$0}'

# 4. PersistentVolumes still bound
kubectl get pv,pvc -A | grep -v Bound

# 5. Node has no problematic taints
kubectl describe node | grep -E "Taint|DiskPressure|MemoryPressure"

# 6. CoreDNS resolves inside the cluster
kubectl run -it --rm dns-test --image=busybox --restart=Never -- \
  nslookup kubernetes.default.svc.cluster.local

11Custom / Locally-Built Images

The RKE2 upgrade replaces the containerd daemon (from 1.7.x to 2.x on the 1.27→1.32 path). This can evict locally-imported images from the containerd image store. Verify that all custom images are present after the upgrade and re-import any that are missing.

Check which images are loaded

/var/lib/rancher/rke2/bin/ctr \
  --address /run/k3s/containerd/containerd.sock \
  -n k8s.io images ls | grep -v "rancher\|k8s.gcr\|registry.k8s"

Re-import a missing image

# Import from a saved tar archive
/var/lib/rancher/rke2/bin/ctr \
  --address /run/k3s/containerd/containerd.sock \
  -n k8s.io images import /path/to/image.tar

# Verify it imported successfully
/var/lib/rancher/rke2/bin/ctr \
  --address /run/k3s/containerd/containerd.sock \
  -n k8s.io images ls | grep your-image-name

After re-importing, restart the affected deployment

kubectl rollout restart deployment/<name> -n <namespace>
kubectl rollout status deployment/<name> -n <namespace>
⚠
Keep image tar archives on persistent storage Images loaded via ctr images import are not backed up by RKE2. Store the original tar files on durable storage (NFS share, object store, local disk outside the container runtime root). After any containerd version bump, re-verify and re-import all custom images.

12Post-Upgrade Disk Cleanup

After the upgrade is fully verified, reclaim disk space by removing old RKE2 data directories and pruning unused container images.

Remove old RKE2 data directories

Each version leaves behind a directory in /var/lib/rancher/rke2/data/. Only the current version's directory is needed.

# List all data directories
ls /var/lib/rancher/rke2/data/

# Remove all except the current version
CURRENT=$(rke2 --version | awk '{print $3}' | sed 's/+/-/')
for dir in /var/lib/rancher/rke2/data/*/; do
  basename=$(basename "$dir")
  if ! echo "$basename" | grep -q "$CURRENT"; then
    echo "Removing old: $basename"
    rm -rf "$dir"
  fi
done

df -h /

Remove zombie pods

Pods with status ContainerStatusUnknown are orphaned from before a node restart and consume no disk, but clutter kubectl get pods output. Remove them with:

# Preview what will be deleted
kubectl get pods -A --field-selector=status.phase=Failed

# Delete Failed pods per namespace
for ns in $(kubectl get ns -o name | cut -d/ -f2); do
  kubectl delete pods -n "$ns" --field-selector=status.phase=Failed \
    --force --grace-period=0 2>/dev/null
done
⚠
Do not delete Completed Spark driver pods automatically Spark driver pods in Completed state are referenced by SparkApplication resources for log retrieval. Delete them only after confirming no audit or log queries are pending.

13Switch CNI from Canal to Calico (Optional)

RKE2 defaults to Canal CNI — Flannel (VXLAN overlay, UDP 4789) + Calico (NetworkPolicy engine). To run pure Calico CNI, where Calico handles both the VXLAN overlay and policy, perform this switch after the full Kubernetes upgrade is verified healthy. Do not combine a CNI switch with a k8s version bump.

ℹ
No extra downloads needed in airgap Calico images (rancher/hardened-calico:v3.31.3+) are bundled inside the RKE2 airgap tarballs from v1.30 onward. After completing the upgrade to v1.32, they are already imported into containerd.
⚠
~2 minutes of pod networking interruption Canal (Flannel) is uninstalled and Calico takes over. All pods temporarily lose connectivity. The flannel.1 interface is replaced by vxlan.calico. Plan a maintenance window.

Automated switch

sudo bash scripts/switch-cni-to-calico.sh

The script: writes cni: calico to /etc/rancher/rke2/config.yaml, restarts rke2-server, waits for the Calico DaemonSet to become Ready, verifies vxlan.calico is up, then restarts all application Deployments and StatefulSets.

Manual steps

# 1. Configure
echo "cni: calico" >> /etc/rancher/rke2/config.yaml

# 2. Restart (Canal removed, Calico deployed)
systemctl restart rke2-server

# 3. Verify Calico is running
kubectl get pods -n kube-system | grep calico
ip link show vxlan.calico      # Calico VXLAN interface
ip link show flannel.1         # should disappear

# 4. Restart pods to pick up new CNI-managed interfaces
kubectl rollout restart deployment -A
kubectl rollout restart statefulset -A

# 5. Confirm all pods recover
kubectl get pods -A

14Rollback Procedure

Kubernetes does not support in-place downgrades. The only supported rollback is to restore etcd from a snapshot taken at the previous version, then re-install the previous RKE2 binary.

🛑
Rollback destroys all state since the snapshot Any data written to etcd after the snapshot (new deployments, config changes, PV bindings) will be lost. Ensure your snapshot is fresh and application data lives in PersistentVolumes (not etcd) before proceeding. 
# 1. Stop the RKE2 server
systemctl stop rke2-server

# 2. Install the previous version binary (must be available as a local tarball)
PREV_VERSION="v1.31.9+rke2r1"
INSTALL_RKE2_ARTIFACT_PATH="/root/rke2-upgrade/${PREV_VERSION}" \
  INSTALL_RKE2_VERSION="${PREV_VERSION}" \
  bash /root/rke2-upgrade/install.sh

# 3. Restore etcd from the pre-upgrade snapshot
SNAPSHOT_NAME="pre-upgrade-202611220522"   # Use your snapshot name
rke2 server \
  --cluster-reset \
  --cluster-reset-restore-path=/var/lib/rancher/rke2/server/db/snapshots/${SNAPSHOT_NAME}

# 4. Start the server (will restart as a single-node cluster)
systemctl start rke2-server

# 5. Verify restoration
kubectl get nodes

15Troubleshooting

Service fails to start after restart

journalctl -u rke2-server --since "5 minutes ago" --no-pager \
  | grep -E "fatal|Error|failed"

Common causes and fixes:

  • CRD registration EOF — transient; systemd will retry within 30 s. Wait and re-check with systemctl status rke2-server.
  • Disk full — run df -h /. If over 95%, clean old RKE2 data directories and re-try.
  • etcd fails to start — check journalctl -u rke2-server | grep etcd. If the etcd snapshot is corrupted, restore from backup.

Node tainted with disk-pressure

# Check current taint
kubectl describe node <name> | grep Taint

# Free space (remove old RKE2 data, prune images)
# Then manually remove stale taint if kubelet hasn't cleared it yet
kubectl taint node <name> node.kubernetes.io/disk-pressure:NoSchedule-

Pods stuck in ImagePullBackOff after upgrade

Custom images may have been evicted from the containerd store during a containerd version upgrade. See section 11 to re-import them.

# Identify which image is missing
kubectl describe pod <pod-name> -n <namespace> | grep "Failed to pull\|Image:"

# Re-import the image
ctr --address /run/k3s/containerd/containerd.sock -n k8s.io \
  images import /path/to/image.tar

Java/Quarkus pods in CrashLoopBackOff after upgrade

Java applications (e.g., Nessie) may fail their startup probe during peak post-upgrade resource contention when all pods restart simultaneously. Restart the deployment once the system has settled:

kubectl rollout restart deployment/<name> -n <namespace>
kubectl rollout status deployment/<name> -n <namespace>

Ranger sidecar failing DNS resolution

Some Ranger sidecar containers try to reach ranger-admin.rangernw — an external hostname that may not be resolvable. If the main Ranger admin pod is healthy, this sidecar failure is expected and does not affect Ranger functionality. Verify with:

kubectl get pods -n ranger
# If ranger-apache-ranger-*  shows 1/1 Running, the admin UI is operational.

16Full Upgrade Checklist

Use this checklist for each upgrade run. Print or copy it to your runbook.

Before starting

  • Free disk on / ≥ 20 GB
  • All nodes Ready, no pending evictions
  • etcd snapshot taken within 1 hour
  • Artifact tarballs downloaded and checksums verified
  • Custom image tar archives confirmed on disk
  • Pre-upgrade service state recorded (kubectl get pods -A > pre-upgrade-state.txt)

For each upgrade step (server)

  • Set TARGET_VERSION to next minor version
  • Installed binary with INSTALL_RKE2_ARTIFACT_PATH (airgap)
  • Verified rke2 --version shows new version
  • Restarted rke2-server
  • Waited for systemctl is-active rke2-server
  • Verified node Ready at new version via kubectl get nodes
  • Canal, CoreDNS, and metrics-server rollout complete

After final upgrade step

  • Upgraded agent nodes and uncordoned them
  • All application pods back to Running
  • All PVCs still Bound
  • Custom images confirmed present in containerd store
  • Old RKE2 data directories removed
  • Zombie pods cleaned up
  • No node taints remaining
  • etcd post-upgrade snapshot saved
